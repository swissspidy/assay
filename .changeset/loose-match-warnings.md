`validateCheckSet` warns about comparisons that accept more than they appear to: an unanchored `regex` with no regex syntax on structured evidence (probe, storage, request or response, URL parts, a URL match's regex or query parameters), which also matches longer values (`/Berlin/` accepts `Europe/Berlin-Test`), a JSON Schema property pinned with `const` or `enum` (also in a combinator branch or through a local `$ref`) that is not in `required`, so a value without it passes, and two or more `sameAs` checks in one requirement comparing the same collections through `items` with different pointers, which pair the fields of different records. The compiler refuses all three, as well as a check that abstains on a valid stress variant of a correct reference (previously a warning), and its discovery prompt asks for exact comparisons of exact values and for a page identity check (URL path, or a heading or landmark) when a requirement names a page, with a record's title compared exactly, and for collections compared as whole records.
